# Design System: GovAI One — 政务智能系统（企业端 / 审批端 / 监管端）

> 面向 Google Stitch 屏幕生成的语义设计规范。目标不是"好看的模板"，而是一套**行政办公、高密度、数据优先**的政务后台语言：让审批人一屏做完决策、让申报人少点一次。所有色值/字体与三端现有代码 token（`--govai-brand`、Element Plus 变量覆盖）同源，新生成屏须落回这些 token。

## 1. Visual Theme & Atmosphere

高密度 Cockpit 界面（Density 8 / Variance 3 / Motion 2）。像政务大厅的办事窗口与数据中心监控屏的结合：浅色干净、克制冷静、层级来自**对齐与信息密度**而非装饰。每一屏只为两件事服务——"这条单能不能过/卡在哪"，以及"下一步操作在哪里"。页面不鼓励自由排版，鼓励把次要说明折叠、把结论提前。信任感来自精确的数据呈现与一致性，不来自华丽的视觉冲击。

- 页面底色为浅灰工作台（#f0f2f5），数据卡片为纯白（#ffffff），形成"卡片浮在台面"的稳定结构。
- 全系统唯一品牌强调色为政务蓝 #2f6bff，只在 CTA、选中、关键状态、主链路引导处出现。
- 数字、单号、证照号、审批码一律以等宽/tabular 呈现，对齐严整。
- 移动/极端动效在本系统属于例外，不做视觉叙事。

## 2. Color Palette & Roles

**品牌与结构**
- **政务蓝 Primary**（#2f6bff）— 全系统唯一强调色：主按钮、激活态、焦点环、关键链接、当前环节。`--el-color-primary`
- **政务蓝深**（#2656cc）— 按钮 hover/active、按下态加深。`--el-color-primary-dark-2`
- **政务蓝墨**（#1a3a8f）— 深蓝品牌底、深色横幅标题、Logo 落点。`--govai-brand-deep`
- **政务蓝淡**（#eaf0ff / #d5e1ff）— 选中行/高亮块底色与浅描边。`--el-color-primary-light-9 / light-8`

**中性基底（Element 灰阶，全程不波动）**
- **工作台灰**（#f0f2f5）— 页面底色。
- **面板灰**（#f5f7fa）— 卡片内分区、代码/摘要底。
- **卡片白**（#ffffff）— 卡片、表格、表单表面。
- **墨色 Ink**（#303133）— 主文字、标题。
- **钢灰**（#606266）— 次级信息、表格正文弱化、描述。
- **雾灰**（#909399）— 辅助说明、时间戳、占位（`.text-muted`）。
- **边框**（#e4e7ed 结构 / #ebeef5 表格细线）— 1px 结构分隔。

**语义状态（沿用 Element 语义对）**
- **Success**（#67c23a / 底 #f0f9eb）— 通过、有效、正常、已办结、守信 A/B。
- **Warning**（#e6a23c / 底 #fdf6ec）— 转人工、待办提醒、临期、信用 C。
- **Danger**（#f56c6c / 底 #fef0f0）— 未过、驳回、已拒绝、风险提示、信用 D。
- **Info**（#909399 / 底 #f4f4f5）— 已注销、历史、停用、中性状态。

**Banned**
- 禁第二强调色并存；禁紫/粉霓虹、彩虹渐变按钮、大面积渐变标题。
- 禁纯黑 #000000 文字（用 #303133 级墨色即可）。
- 深色语义仅用于明确的风险/告警横幅与监管大屏底色，不得做整站暗色主题混排。

## 3. Typography Rules

- **栈**：`'Helvetica Neue', Helvetica, 'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', sans-serif`。中文字形是主体；Stitch 生成中文屏不得改用西文衬线或创意 Display 字形做正文/标题。
- **数字/单号等宽**：金额、面积、人数、证照号、信用代码、时间、单号列使用 `tabular-nums`；在表格与台账中尤其如此，保证同列逐位对齐。
- **字号刻度（Element 对齐）**
  - 页面标题 20px / 600 — 每个页面唯一
  - 卡片区块标题 16px / 600（左 4px 蓝条 `#2f6bff` 的 `.section-title`）
  - 组件面板内小标题 14px / 600
  - 表格/表单正文 13px（高密度桌面固定档）
  - 辅助/时间戳 12px / #909399
- **行高**：正文 1.6–1.8；表格内 1.4–1.5；列表卡片行高 1.7 左右，中文不挤。
- **规则**：不用超大 Display 字做后端页标题；标题层级靠字重 + 间距，不靠字号飙高。Banned：衬线正文/标题、全大写西文、首行缩进排版。

## 4. Component Stylings

- **按钮**：主按钮政务蓝实底 #2f6bff、白字；次按钮描边白底；文本/链接按钮用于表格行内操作。禁用发光/外发光。按下有 -1px 触感反馈，危险操作用 Danger 语义色而非主色。AI/长任务按钮内嵌"研判中…"加载态。
- **表格（一等公民）**：高密度 `size="small"`，行高约 36–40px。首列放业务编码/证照号等真实标识，**禁止露出自增主键 id**。行 hover 提亮、关键状态列用语义 el-tag。**一屏内不出现横向滚动**——列过多时做列收纳或摘要。分页置底。
- **卡片 `.section-card`**：白底、8px 圆角、1px #ebeef5 边框、轻投影 `0 1px 4px rgba(0,21,41,.06)`，纵向间距 16px。卡片只表达信息归属，不层层套卡；高密度区用分隔线代替再嵌卡片。
- **表单**：顶部 `.filter-bar` 内联筛选项水平排布；业务表单 label 上置或左侧固定 120px；错误态行下红字说明原因；必填红星；上传区虚线框 hover 变蓝。提交前有合规预检回执，失败项逐条红字列出并允许返回修改或坚持提交。
- **状态/标签**：状态一律 el-tag + 语义色短词（通过/未过/受理中/办结/退回/已注销/转人工），禁 emoji 表情替代。
- **智能审核区**（审批详情核心）：结论为顶部语义横幅（绿=通过/橙=转人工/红=未过）+ 一句处置建议；规则明细表格显示"校验字段 / 类型 / 申报值 / 结果 / 提示"，通过项不再显示错误文案；AI 意见默认折叠为摘要（建议决定 + 首条核查 + 风险红字），要点逐条一行，点"展开全部"才全显。**突出结论、默认收敛、无装饰符号**。
- **空态**：插图 + 说明 + 一条下一步动作（如"去办事大厅申报""重新生成AI意见"），不只有"暂无数据"。
- **加载**：表格/列表用骨架屏；按钮/提交用内联 loading；不默认全屏转圈。

## 5. Layout Principles

- 三端统一工作台结构：顶栏（系统名/当前端身份/用户）+ 左侧功能导航 + 内容区（浅灰 #f0f2f5）。
- **列表页**：`.filter-bar`（筛选/搜索/操作按钮）→ 高密度表格 → 分页，三者恒定纵向顺序。
- **详情页（审批）**：顶部"概要卡"放事项名/申请人/状态/当前环节/当前岗位操作按钮（操作上提，减少滚动）→ 申报表单 → 智能审核区 → 审批记录时间线。
- 栅格以 24 列为基础，卡片用 8/16、10/14 等非对称分配，避免三张等宽卡一字排开做装饰。
- 正文容器 max-width 参考 1440px；监管大屏另按宽屏指标，但监控数值仍用真实接口字段、注明数据来源。
- **禁止**：元素重叠、absolute 堆叠内容、flex 百分比 hack 实现布局、卡片套卡超 3 层。

## 6. Motion & Interaction

- 桌面后台默认静止克制：Element 标准 300ms 淡入/滑出即可，无装饰循环动画。
- 可保留的状态微交互：按钮按压缩放、标签出现、表行 hover 提亮、折叠展开、消息淡入。
- 弹窗/抽屉标准过渡；数据刷新用局部更新而非整页闪动。
- 遵守 `prefers-reduced-motion`；AI 生成/后台推送等长任务给确定性进度文字而非空转。
- 监管大屏如需滚动大屏数字/滚动条，频率降低并可在高对比模式下收敛，不作叙事动画。

## 7. Anti-Patterns（Banned）

- **禁止 emoji** 出现在任何界面状态或文案中（用 el-tag/图标组件）。
- 禁止露出自增主键 id 列；真实业务标识放首列。
- 禁止假指标与包装数字（"99.99%""全流程 100% 秒批"）——政务数据必须来自库/接口并标注状态。
- 禁止 AI 营销套话（"赋能""闭环""生态""Next-Gen""无缝"）作为界面文案；用动作性、结论性语言。
- 禁止霓虹/渐变按钮、紫色强调、纯黑正文、彩虹分隔。
- 禁止 Inter / 衬线正文 / 大写西文标题；后端界面禁止 Editorial 式超大 Display。
- 禁止三张等宽空白特性卡做版面装饰；禁止无意义 Hero 与"向下滑动"类引导。
- 禁止横向滚动；<768px 一律单列；交互目标 ≥44px。
- 禁止让审批人阅读超长 AI/规则原文堆叠——凡长文本必须折叠或摘要在前。
- 禁止泛化占位（"张先生/某公司"），演示数据用可读的规范主体名。
